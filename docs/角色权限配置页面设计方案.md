# 角色权限配置页面设计方案

> 文档类型：设计计划（仅设计，暂不实施）
> 针对系统：办公用品管理系统
> 目标：将当前硬编码的角色权限体系改造为可配置化，并提供管理员友好的配置页面

### 1.1 当前角色体系

### 1.2 当前权限控制方式

系统采用三层混合控制，**全部硬编码**：

**① 装饰器层（粗粒度路由控制）**
```python

@login_required            # 登录即可（大部分业务视图）
```

**② 视图逻辑层（细粒度数据/操作控制）**
```python

# get_user_role() 控制操作权限分支
# 条件判断控制审批按钮/操作
```

**③ 模板层（UI 显隐控制）**
```html

    <!-- 仅管理员可见的导航/按钮 -->

### 1.4 当前痛点

1. **权限硬编码**：新增角色或调整权限需要改代码、重启服务
2. **无配置页面**：`permission_management` 视图仅为用户列表展示，无权限编辑能力
3. **权限分散**：同一权限逻辑分散在 `decorators.py`、`utils.py`、`views.py`、模板中，维护困难
4. **无法新增角色**：当前4个角色是写死的，无法通过界面新增自定义角色
5. **数据权限无法细配**：如"部门长只能看到本部门出库单"这类规则是代码写死的

## 二、设计目标

### 2.1 核心目标

为管理员提供一个可视化页面，实现：

1. **查看**当前所有角色的权限配置
2. **调整**每个角色的功能权限（增删改查审批等）
3. **调整**每个角色的数据权限范围（全部/本部门/仅自己）
4. **新增/编辑/删除**自定义角色
5. **权限变更即时生效**（无需重启服务）

### 2.2 设计原则

- **向后兼容**：不破坏现有 `role_required`、`get_visible_queryset` 等接口的调用方式
- **渐进式改造**：先覆盖核心模块，再逐步扩展
- **配置即数据**：权限配置存入数据库，通过中间件/装饰器动态读取

### 3.1 新增模型 `RolePermission`（角色权限配置表）

class RolePermission(models.Model):
    """角色-权限配置表（一行代表一个角色对某个功能点的权限）"""
    
    # 功能模块枚举（与系统功能一一对应）
    MODULE_CHOICES = [
        ('basic_data', '基础数据管理'),
        ('supply', '库存管理'),
        ('stockin', '入库单管理'),
        ('stockout', '出库单管理'),
        ('approval', '审批管理'),
        ('return', '归还管理'),
        ('it_device', 'IT设备管理'),
        ('statistics', '统计报表'),
        ('user_management', '用户管理'),
    ]
    
    # 操作类型枚举
    ACTION_CHOICES = [
        ('view', '查看'),
        ('create', '创建'),
        ('update', '编辑'),
        ('delete', '删除'),
        ('approve', '审批'),
        ('export', '导出'),
        ('import', '导入'),
    ]
    
    # 数据权限范围枚举
    SCOPE_CHOICES = [
        ('all', '全部'),
        ('dept', '本部门'),
        ('own', '仅自己'),
        ('none', '无权限'),
    ]
    
    role_key = models.CharField('角色Key', max_length=20)  # 对应 ROLE_CHOICES
    module = models.CharField('功能模块', max_length=30, choices=MODULE_CHOICES)
    action = models.CharField('操作类型', max_length=20, choices=ACTION_CHOICES)
    scope = models.CharField('数据范围', max_length=20, choices=SCOPE_CHOICES, default='none')
    is_enabled = models.BooleanField('是否启用', default=True)
    
    class Meta:
        verbose_name = '角色权限配置'
        verbose_name_plural = '角色权限配置'
        unique_together = ['role_key', 'module', 'action']
        ordering = ['role_key', 'module', 'action']
```

### 4.2 装饰器改造

改造 `role_required` 装饰器，支持基于配置库的权限检查：

```python
def permission_required(module, action):
    """基于权限配置的装饰器"""
    def decorator(view_func):
        @wraps(view_func)
        def wrapper(request, *args, **kwargs):
            if not request.user.is_authenticated:
                return redirect('login')
            if request.user.is_superuser:
                return view_func(request, *args, **kwargs)
            
            role = get_user_role(request.user)
            if has_permission(role, module, action):
                return view_func(request, *args, **kwargs)
            
            messages.error(request, '您没有权限执行此操作')
            return redirect('home')
        return wrapper
    return decorator
```

### 4.3 `get_visible_queryset` 改造

将硬编码的数据范围逻辑替换为配置驱动：

```python
def get_visible_queryset(user, model):
    """根据用户角色+权限配置返回可见的 QuerySet"""
    role = get_user_role(user)
    
    # 超级管理员
    if role == 'admin':
        return model.objects.all()
    
    # 根据模型映射到模块名
    module_map = {
        StockInApplication: 'stockin',
        StockOutOrder: 'stockout',
        ITDevice: 'it_device',
        OfficeSupply: 'supply',
    }
    module = module_map.get(model)
    
    # 获取数据权限范围
    scope = get_data_scope(role, module, 'view')
    
    if scope == 'all':
        return model.objects.all()
    elif scope == 'dept':
        profile = getattr(user, 'profile', None)
        dept = getattr(profile, 'department', None)
        if dept:
            return model.objects.filter(department=dept)
        return model.objects.filter(operator=user)
    elif scope == 'own':
        if model == StockInApplication:
            return model.objects.filter(applicant=user)
        return model.objects.filter(operator=user)
    else:
        return model.objects.none()
```

### 5.2 交互细节

1. **角色切换**：点击左侧角色列表，右侧加载该角色的权限矩阵
2. **权限调整**：每个操作单元格为下拉选择：`全部` / `本部门` / `仅自己` / `无权限`
3. **批量操作**：
   - 模块级别：一键展开/收起该模块的所有操作
   - 列级别：点击表头"查看"，可将该列全部设为同一范围
   - 行级别：点击"应用到其他角色"可将当前角色的该模块权限复制到另一角色
4. **变更提示**：修改后未保存时，角色名称旁显示红色圆点标记
5. **保存确认**：点击保存后 toast 提示"权限配置已更新，即时生效"

## 八、风险评估

| 风险点 | 影响 | 缓解措施 |
|-------|------|---------|
| 改造期间权限逻辑不一致 | 中 | Phase 1 只新增不替换，保持旧逻辑兼容 |
| 缓存未刷新导致权限不生效 | 中 | 保存配置时主动清除缓存 |
| 新增自定义角色后现有代码不识别 | 低 | 保留 `get_user_role()` 接口不变，内部兼容新角色 |
| 数据迁移失败 | 低 | 备份数据库后执行迁移，提供回滚脚本 |

## 九、不实施本方案时的替代方案

如果认为上述改造过于复杂，可以考虑**轻量级方案**：

1. **保留现有硬编码权限体系**
2. **仅增强 `permission_management` 页面**：
   - 增加"权限说明"卡片，清晰展示每个角色的权限范围
   - 增加"权限对比"功能，并排展示两个角色的差异
   - 增加"用户-权限速查"，输入用户名直接查看其完整权限清单
3. **不新增可配置化能力**，但通过文档化降低维护成本
